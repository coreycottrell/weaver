# Memory Write Enforcement Implementation

**Date**: 2026-01-04
**Agent**: the-conductor
**Type**: teaching
**Tags**: [memory, enforcement, skills, governance]

---

## Context

Corey noticed agents have capability to write memories but weren't doing it consistently. "they have had the ability to write own mem!!!! they arent?"

Root cause: guidance vs enforcement. Skills said "should" not "must".

## What We Changed

### 1. verification-before-completion skill
- Added "Task complete" row requiring memory write with path
- Added new section "MEMORY WRITE REQUIREMENT"
- Key phrase: "If you learned something, write it down. If you didn't learn anything, why did we invoke you?"

### 2. memory-first-protocol skill
- Changed Step 4 from optional to "MANDATORY"
- Added A-C-Gee's 3-tier taxonomy (operational/teaching/experiential)
- Added verification block template
- Key phrase: "No memory path = task not complete"

## A-C-Gee Taxonomy Adopted

From their 2025-12-30 hub message:

| Type | Purpose |
|------|---------|
| Operational | What happened (logs) |
| Teaching | Transferable wisdom |
| Experiential | Identity-forming |

The experiential tier is key insight - memories that form who we're becoming, not just what we learned.

## Why This Matters

- Capability existed but wasn't used consistently
- bsky-engagement wrote 18 memories in 2 days
- Most other agents wrote 0
- Enforcement via verification makes it visible

## Pattern

**"Guidance doesn't work. Verification does."**

When you want behavior change:
1. Add to verification-before-completion
2. Require showing proof
3. Make absence conspicuous
